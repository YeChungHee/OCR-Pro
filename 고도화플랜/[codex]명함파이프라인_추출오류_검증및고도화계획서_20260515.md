# [codex] 명함 파이프라인 추출오류 검증 및 고도화계획서

**작성일:** 2026-05-15  
**기준 버전:** OCR Pro v9.44  
**대상 파이프라인:** 이미지/명함 입력 파이프라인 `CardSplitLearner`  
**목적:** 첨부 명함 7건과 OCR Pro 화면 결과를 기준으로 회사명, 대표자, 담당자, 전화, 이메일, 웹주소 필드 오분류 원인을 검증하고, 다른 입력 파이프라인에 영향을 주지 않는 명함 전용 고도화 계획을 정의한다.

---

## 1. 핵심 결론

현재 오류는 OCR 텍스트 자체가 완전히 비어 있는 문제가 아니라, OCR 결과에서 어떤 줄을 회사명/대표자/담당자로 승격할지 결정하는 필드 분류 규칙의 문제다.

특히 다음 세 가지가 반복된다.

1. 영문 슬로건이 사람 이름 또는 대표자 후보로 승격된다.
2. 업종/역할 문구가 회사명으로 승격된다.
3. 로고/도메인/웹주소에 있는 실제 회사 식별자가 회사명 보정에 충분히 사용되지 않는다.

따라서 즉시 구현 방향은 `CardSplitLearner` 내부에만 적용되는 명함 전용 후처리 검증기, 회사명 후보 랭킹, 사람명 후보 검증, 도메인 기반 보정기를 추가하는 것이다.

## 3. 코드 기준 원인 검증

### 3.1 현재 적용된 보호장치

현재 v9.44에는 다음 장치가 이미 있다.

- `CardSplitLearner`: 이미지/명함 파이프라인 전용 학습 엔진
- `normalizeBusinessCardImageRecords()`: 명함 레코드 후처리
- `parseOcrTextWithAI()`: Vision OCR 후 Gemini 구조화 우선 시도
- `parseFullTextToRecords()`, `parseBusinessCard()`: AI 실패 시 정규식 폴백
- `CORE_EXTRACTION_FIELD_PRIORITY`: 회사명, 사업자번호, 대표자, 이메일, 연락처 우선순위
- `buildSalesMapPayload()`: SalesMap 회사/개인 DB 구조 저장용 payload

### 3.2 남은 취약점

1. `EN_NAME_LINE_RE`가 `Quality Marketing Quality` 같은 3단어 영문 슬로건을 인명처럼 볼 수 있다.
2. `NON_NAME_KO`와 `SKIP_LABEL_SET`에 `전문기업`, `전문평가위원`, `인지기반위원장`, `Quality Marketing Quality` 같은 현재 샘플의 오분류 단어가 충분히 반영되어 있지 않다.
3. 회사명 후보 점수(`cardCompanyScore`)는 법인 suffix에 강하지만, 로고형 브랜드명과 도메인 기반 회사명에는 약하다.
4. AI 경로와 정규식 경로 모두 최종 단계에서 “회사명 후보가 실제 회사명인지” 검증하는 공통 validator가 없다.
5. 회사명이 이미 오분류 값으로 채워진 경우 Stage 5 도메인 추론이 작동하지 않는다. 즉, 빈 회사명만 보정하고 잘못 채워진 회사명은 교체하지 못한다.

## 4. 고도화 목표

명함 파이프라인의 최종 목표 필드는 다음 순서로 고정한다.

1. 회사명
2. 사업자번호
3. 대표자
4. 담당자
5. 전화 또는 휴대폰
6. 이메일
7. 웹주소
8. 주소

SalesMap 저장 관점에서는 다음 구조를 지킨다.

- Organization: 회사명, 사업자번호, 웹주소, 주소, 일반전화, 대표자
- People: 이름, 직함, 휴대폰, 이메일

## 5. 구현 계획

### Phase 1. 명함 전용 필드 검증기 추가

`CardSplitLearner` 내부 또는 인접 위치에 `BusinessCardFieldValidator`를 추가한다.

검증 규칙:

- 회사명 후보 금지어:
  - `전문기업`, `전문평가위원`, `위원장`, `인지기반위원장`, `Quality Marketing Quality`, `All Business Connector`, `수산양식기술 전문기업`
- 대표자/담당자 후보 금지어:
  - 영문 슬로건, 3단어 이상 일반 영문구, 직무/부서/업종 문구
- 담당직함 후보:
  - `대표`, `대표이사`, `CEO`, `위원장`, `전무`, `이사`, `전문평가위원` 등은 이름이 아니라 직함/역할로 분리
- 회사명 후보 인정:
  - `(주)`, `주식회사`, `㈜`, `재단`, `기금`, `사무소`, `Corporation`, `Corp`, `Inc`, `AISH`, `INNOS` 등 로고형 브랜드

적용 범위:

- `source === "이미지"` 또는 `_pipeline === "IMG"`일 때만 실행
- QR, 문서, URL, 전시회 파이프라인에는 적용하지 않음

### Phase 2. 회사명 후보 랭킹 강화

`rankBusinessCardCompanyCandidates(rawText, rec)` 함수를 추가한다.

가중치 예시:

| 조건 | 점수 |
|---|---:|
| 법인 suffix 포함 | +100 |
| 로고/대문자 브랜드 + 이메일/웹 도메인 일치 | +90 |
| 도메인 base와 유사한 텍스트 | +80 |
| 기관명 suffix: 기금, 협회, 사무소, 센터 | +70 |
| 업종/수식어: 전문기업, 기술, 품질, 마케팅, 커넥터 등 단독 문구 | -80 |
| 직함/역할: 대표, 위원장, 전문평가위원 | -100 |
| 사람 이름 패턴 | -100 |

기대 효과:

- `수산양식기술 전문기업`보다 `(주)슈니테크` 또는 `shuny.co.kr → shuny → 슈니테크` 우선
- `전문평가위원`보다 `기술보증기금` 우선
- 빈 회사명인 AISH/INNOS는 로고 또는 도메인 기반으로 보강

### Phase 3. 도메인 기반 회사명 보정 확장

현재 Stage 5는 회사명이 비어 있을 때만 도메인 기반 추론을 한다. 이를 잘못된 회사명에도 적용한다.

보정 조건:

- 현재 회사명이 금지어/직함/업종 문구인 경우
- 현재 회사명이 2단어 이상 영문 슬로건이고 이메일 또는 웹주소 도메인과 무관한 경우
- 현재 회사명이 담당직함 또는 역할 문구와 일치하는 경우

도메인 보정 예시:

| 도메인 | 보정 후보 |
|---|---|
| `shuny.co.kr` | `(주)슈니테크` |
| `aish.co.kr` | `AISH` |
| `innos-inc.com` | `이노스` 또는 `INNOS` |
| `zerocorp.co.kr` | `주식회사 제로코퍼레이션` |
| `kibo.or.kr` | `기술보증기금` |

초기에는 하드코딩보다 `OCRLearner` aliasMap에 우선 저장하고, 사용자가 회사명 셀을 수정하면 다음부터 자동 보정되도록 한다.

### Phase 4. 대표자/담당자 라우팅 강화

명함에서 사람 이름이 발견되면 다음 순서로 배정한다.

1. 이름 주변에 `대표`, `대표이사`, `CEO`가 있으면 `대표자`
2. 이름 주변에 `전문평가위원`, `위원장`, `전무`, `이사`, `부장` 등이 있으면 `담당자 + 담당직함`
3. 명함에 대표자 표지가 없지만 사람이 1명뿐이면 `담당자`로 우선 배치하고, 대표자 확정은 Bizno/검색 보강 이후 수행
4. 영문 슬로건은 `담당자`, `대표자` 어느 쪽에도 넣지 않음

샘플 기대:

- `Quality Marketing Quality` → 담당자/대표자 금지, 필요 시 영문명/슬로건 후보로만 보관
- `정승호 CEO` → 대표자 `정승호`, 담당직함 `CEO`
- `김만곤 전문평가위원` → 담당자 `김만곤`, 담당직함 `전문평가위원`
- `정종화 대표` → 대표자 `정종화`

### Phase 5. 검수 상태 UI 강화

명함 전용 validator가 다음 상황을 감지하면 신뢰도를 낮추고 검수 사유를 저장한다.

- 회사명이 업종/직함 금지어와 일치
- 대표자/담당자가 영문 슬로건으로 의심
- 이메일/웹주소는 있으나 회사명이 도메인과 불일치
- 회사명이 비어 있고 도메인 보정 후보만 존재

추가 메타:

- `_cardFieldIssues`
- `_companyCandidateSource`
- `_personCandidateSource`
- `_domainCompanyCandidate`
- `_needsReview = true`

- 회사명 금지어 0건
- 대표자/담당자 영문 슬로건 0건
- 이메일 추출률 100%
- 전화/휴대폰 추출률 100%
- 웹주소 추출률 80% 이상
- 사업자번호는 명함 원본에 없는 경우 보강 대상 표시

1. `BusinessCardFieldValidator` 추가

7. v9.45로 배포

## 8. v9.45 완료 기준

v9.45는 다음 조건을 만족해야 한다.

- 위 7개 샘플에서 회사명 필드에 직함/업종/슬로건이 들어가지 않는다.
- 대표자 필드에 영문 슬로건이 들어가지 않는다.
- 담당자 필드는 사람 이름만 허용한다.
- 회사명이 비어 있으면 웹주소/이메일 도메인 기반 후보를 표시한다.
- 모든 변경은 명함 이미지 파이프라인에만 적용된다.
- QR, 문서, URL, 전시회 파이프라인의 파싱 함수는 수정하지 않는다.

## 9. 최종 판단

현재 명함 오류는 v9.44 SalesMap 저장 구조 문제와 별개다. v9.44는 저장 구조를 맞췄고, 이번 오류는 그 이전 단계인 `이미지 → OCR → 필드 구조화` 단계의 분류 정확도 문제다.

따라서 다음 고도화는 v9.45로 분리하여 `CardSplitLearner` 전용 필드 검증/보정 레이어를 구현하는 것이 가장 안전하다.
